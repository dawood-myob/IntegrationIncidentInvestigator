# AI investigation

The prompt identifies evidence as untrusted data and directs the model to use only supplied facts, distinguish confidence levels, avoid unsupported root causes, return a structured JSON object, and provide concise evidence summaries rather than hidden chain-of-thought. Historical matches are context, not proof.

The user reviews file inclusion before starting the request. Text is size-bounded; logs are streamed into bounded excerpts. HTML diagnostic audits are read as bounded source text without browser rendering/script execution. The current version never sends image bytes. OpenAI/Claude secrets are read from environment variables, and GitHub Copilot uses separate CLI sign-in. Home-screen provider indicators check whether API keys are configured and whether Copilot CLI is signed in; they do not verify network connectivity, billing, or selected-model access. The status check sends no incident data. Provider and editable model selection are explicit; no Mock provider or automatic fallback ships with the app. Offline tests use a test-only fake.

Investigation requests include the versioned `IncidentInvestigationResponse.v1.schema.json` contract. OpenAI-compatible clients use strict Chat Completions JSON schemas, Claude uses Messages `output_config.format`, and GitHub Copilot passes the schema through the SDK's currently experimental ResponseSchema API (pinned SDK version). Only models/endpoints supporting these features should be selected. Evidence statements must cite a supplied filename, the problem description, or a historical incident; statements without a source are rejected and no results are saved. Incomplete/blocked/refused responses fail visibly; malformed output is not saved. JSON errors show only numeric positions, never incident content.

`jiraStory` is a typed object with title, objective, user story, description, quoted errors, scope and acceptance criteria. The parser rejects missing/empty required sections and the application renders headings, bullets and numbered criteria deterministically. The prompt requires exact source filenames, validation values/reference types, execution timestamps and impact only when supplied; separates confirmed causes from hypotheses; and requests safe reprocessing, duplicate prevention, reconciliation and diagnostic evidence as future acceptance conditions where relevant. It does not embed facts from the user's example incident or treat historical comments as the current cause. Include known follow-up/root-cause notes in the problem description for review. Attachments are appended from actual user choices rather than claimed already attached. More capable models can improve analysis, but output remains advisory and must be reviewed.

Copilot sessions use Empty mode with no tools, replaced system instructions, disabled memory/session store and disabled session telemetry. Request cancellation/timeout aborts the session and disposal stops the owned runtime. Request compression is not configured for the Copilot SDK transport; gzip would reduce transfer bytes, not model inference time. GitHub Copilot is distinct from Microsoft 365 Copilot/Studio, which this version does not integrate. Review provider retention and SDK-local data policies before sending sensitive evidence.
